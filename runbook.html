01 — Runbook คืออะไร

ต่างจากเอกสารอื่นในไซต์นี้อย่างไร

ไซต์นี้มีเอกสารสามชั้นที่ตอบคนละคำถาม — สับสนกันบ่อยเวลาเกิดเหตุจริงเพราะเปิดผิดเอกสารแล้วเสียเวลา

GUIDE (เช่น postgresql-pgpool-cluster-guide.html)

"ระบบนี้ทำงานยังไง / setup ยังไง"

อ่านตอนออกแบบ/ติดตั้งระบบ — ลึก ครบ มี rationale และ known-gap ทุกจุด อ่านทั้งฉบับใช้เวลาเป็นชั่วโมง

INCIDENT LOG (ในตัว guide เอง §accident/§bugs)

"ครั้งที่แล้วเกิดอะไรขึ้น เราแก้ยังไง"

บันทึกประวัติศาสตร์แบบละเอียด พร้อม output จริงและบั๊กที่เจอระหว่างทาง — มีบริบทเยอะ อ่านเข้าใจทั้งเรื่องแต่ไม่ได้ออกแบบมาให้ไล่ทำตามเร็วๆ

RUNBOOK (หน้านี้ + เอกสารย่อย)

"ตอนนี้ทำอะไร ตามลำดับ"

กลั่นจาก guide + incident log ให้เหลือแค่คำสั่งที่ต้องรัน เรียงเป็นขั้นตอน อ่านจบใน 2–3 นาทีตอนมือไม้สั่นเพราะ prod ล่ม

02 — โครงสร้างมาตรฐาน

ทุก Runbook ในชุดนี้ต้องมี 6 หัวข้อนี้เรียงตามลำดับ

เขียน Runbook ใหม่ให้ copy shell ของ runbook-pgpool-nodes-down.html แล้วแทนเนื้อหา — อย่าออกแบบโครงใหม่ เพื่อให้คนอ่านคุ้นเคยว่าข้อมูลที่ต้องการอยู่ตรงไหนเสมอไม่ว่าจะเป็นเรื่องอะไร

1

อาการ (Symptom)

error message / log line ที่เห็นจริงๆ แบบ copy มาตรงๆ ไม่ paraphrase — ใช้ค้นหา/แม็ตช์เหตุการณ์ได้ทันที

2

ผลกระทบ (Impact)

อะไรพังบ้าง ระดับความรุนแรงแค่ไหน ต้องรีบแค่ไหน — ช่วยตัดสินใจว่าควร escalate หรือรอได้

3

วินิจฉัย (Diagnosis)

คำสั่งที่ใช้ยืนยันว่าใช่เคสนี้จริง ก่อนเริ่มแก้ — กันแก้ผิดจุดตอนตื่นตกใจ

4

สาเหตุ (Root Cause)

อธิบายสั้นๆ ว่าทำไมถึงเกิด — พอให้เข้าใจว่าทำไม fix ข้อ 5 ถึงใช้ได้ ไม่ต้องลึกเท่า guide

5

การแก้ไข (Fix)

คำสั่ง copy-paste ได้ตรงๆ เรียงตามลำดับที่ต้องรันจริง

6

ยืนยัน + ป้องกัน (Verify / Prevent)

เช็คยังไงว่าหายจริง + ลิงก์ไปเอกสารเชิงลึก/mitigation ระยะยาวถ้ามี

03 — รายการ Runbook

Database / Infrastructure

PGPOOL · DATABASE

Pgpool: All Backend Nodes Down

App ทุกตัว connect DB ไม่ได้ (pgpool is not accepting any new connections) ทั้งที่ PostgreSQL/repmgr จริงปกติ

PM2 · DISK

Disk เต็มจาก pm2 Logs

/root/.pm2/logs/ โตหลาย GB เพราะ pm2 ไม่มี log rotation ให้ โดย default — รวมกับดัก rm ไฟล์ที่ยังเปิดอยู่แล้วพื้นที่ไม่คืน

PROXMOX · HARDWARE

Proxmox Host รีบูตเอง (CPU MCE)

Hypervisor ดับเองไม่มี shutdown log · VM ตายพร้อมกันหมด · Linux ไม่บันทึกอะไรเลยเพราะฮาร์ดแวร์รีเซ็ตก่อน — วินิจฉัยด้วย BERT + BMC SEL

PGPOOL · DATABASE

Standby ค้าง down หลัง apt Auto-Upgrade

status=down แต่ pg_status=up · auto_failback เปิดอยู่แต่ไม่ทำงานเพราะ application_name ไม่แมตช์ — เงียบสนิท ไม่มี alert

ยังไม่มี runbook สำหรับหมวดอื่น (RabbitMQ jam, MinIO/storage, IAM permission sync ฯลฯ) — เพิ่มเข้ามาเมื่อเจอเหตุการณ์จริงและอยากกันไม่ให้ทีมเสียเวลาซ้ำ
