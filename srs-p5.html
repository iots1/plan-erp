Core Use Cases & Data Entry · บันทึกข้อมูลยังไง

1

รับ event stock.deducted (allocations พร้อม unit_cost) → คำนวณ COGS ต่อ allocation = qty × lot.unit_cost → บันทึก cogs_entries ต่อล็อต

2

ดึงราคาขาย จาก sales-bc (TCP) → คำนวณ กำไรต่อล็อต = revenue − COGS → บันทึก profit_loss_records ต่อ allocation

3

ออกใบกำกับภาษี (Tax Invoice) อ้างอิง delivery/SO → คำนวณ VAT (ภาษี 1/ภาษี 2), เลขที่ใบกำกับแบบต่อเนื่อง → emit invoice.issued

4

ใบวางบิล (Billing Note) รวมหลายใบกำกับเพื่อเรียกเก็บเงินรอบเดียว

Tax Invoice ต้องอ่าน 2 แหล่งข้อมูล — คนละ BC

ขั้นตอน "คำนวณ VAT" ในข้อ 3 ต้องดึงข้อมูล 2 ที่: (1) tax_categories + products.tax_category_id (inventory-bc, มีโค้ดแล้ว — ดู P2) บอกว่าสินค้าแต่ละบรรทัด standard/zero_rated/exempt และ price_lists.is_tax_inclusive บอกว่าราคาที่ตกลงรวม VAT แล้วหรือยัง (2) TAX_CONFIGS (finance-bc, ตารางด้านล่าง) เก็บอัตราภาษีจริงที่ใช้คำนวณ (VAT7/WHT) — สองตารางนี้คนละหน้าที่กัน: inventory-bc บอก "สินค้านี้ประเภทไหน", finance-bc บอก "อัตราจริงเท่าไหร่และคำนวณยังไง" ต้องเรียกผ่าน TCP ข้าม BC เสมอ ไม่ query ตรง

Edge Cases · กรณีขอบเขต

แก้ใบกำกับที่ออกแล้ว

ใบกำกับที่ออกแล้ว ห้ามแก้ ต้องออก ใบลดหนี้/เพิ่มหนี้ (credit/debit note) แทน

COGS event มาช้า

ถ้า allocation (stock.deducted) มาช้ากว่า invoice → คำนวณ COGS แบบ provisional แล้ว reconcile เมื่อ event มาถึง

สินค้าคืน (Return)

ต้อง กลับรายการ COGS และคืนสต็อกเข้าล็อตเดิม พร้อมออกใบลดหนี้

หลายอัตราภาษี

รองรับสินค้าที่ยกเว้นภาษี/หลายอัตราในใบเดียว คำนวณแยกบรรทัด

Developer Implementation Guide · คำสั่งจาก SA

RULE · EXACT LOT COST

COGS = Σ(allocation.qty × allocation.unit_cost) ต้องใช้ unit_cost ที่มากับ event เท่านั้น ห้ามคำนวณเฉลี่ย และห้าม query ราคาปัจจุบันของสินค้า

RULE · PER-ALLOCATION P&L

คำนวณกำไรต่อ allocation แล้วค่อย aggregate — หนึ่ง delivery อาจกินหลายล็อตที่ต้นทุนต่างกัน

RULE · IMMUTABLE COGS

COGS เก็บเป็น snapshot immutable แก้ไขผ่าน adjusting entry เท่านั้น

RULE · GAPLESS NUMBERING

เลขที่ใบกำกับต้อง gapless & transaction-safe (ใช้ advisory lock / sequence table) กันเลขซ้ำ/ข้าม

RULE · DECIMAL & ROUNDING

ใช้ decimal(18,4) หรือ integer สตางค์ · ปัดเศษตามกฎภาษี · ห้าม float

RULE · IDEMPOTENT CONSUMER

consumer ของ stock.deducted ต้อง idempotent (processed_events) กันการสร้าง COGS ซ้ำ

RULE · INVOICE IMMUTABILITY

ใบกำกับที่ออกแล้ว immutable → แก้ไขด้วย credit/debit note pattern เท่านั้น

RULE · GL DOUBLE-ENTRY BALANCED

ทุก financial transaction โพสต์ลง GL เป็นคู่ debit = credit เสมอ (ยอดรวมต้องเป็นศูนย์) · GL เป็น append-only + immutable เหมือน stock ledger · การ cancel เอกสารต้องโพสต์ entry กลับด้าน ไม่ลบของเดิม

RULE · PAYMENT ALLOCATION

1 การชำระเงิน allocate ไปได้ หลายใบกำกับ · ผลรวม allocation ≤ paid_amount · ส่วนเกินเก็บเป็น unallocated_amount (เครดิตลูกค้า) · outstanding ของใบกำกับ = total − Σ allocation

RULE · WITHHOLDING TAX

รองรับภาษี หัก ณ ที่จ่าย (WHT) แยกจาก VAT — ตอนรับ/จ่ายเงินคำนวณ WHT ตามอัตราของประเภทเงินได้ แล้วออกหนังสือรับรองหัก ณ ที่จ่าย · WHT ลดยอดเงินสดจริงแต่ไม่ลดยอดหนี้

1

ตั้งอัตราภาษีก่อนออกใบ — POST /tax-configs สร้าง VAT7 (tax_type=vat, rate=7, effective_from) · ถ้าไม่มี config ที่มีผล ระบบคิด VAT 0% แล้วออกใบได้ปกติ (บริษัทที่ไม่จด VAT ก็ต้องออกใบได้) ไม่ใช่ error

2

ทดสอบเลข gapless — สร้างร่าง 3 ใบ ลบทิ้ง 1 ใบ แล้ว issue อีก 2 ใบ → เลขต้องเป็น 00001, 00002 ติดกัน ไม่ข้าม (พิสูจน์ว่าเลขไม่ได้จ่ายตอน create) · ยิง issue พร้อมกัน 2 request บนใบเดียว → ได้เลขเดียว อีกอันได้ 409

3

ทดสอบภาษีผสมในใบเดียว — ใส่ 3 บรรทัดที่สินค้ามี tax_category ต่างกัน (standard / zero_rated / exempt) → total_standard_vat_price, total_zero_vat_price, total_exempt_vat_price ต้องแยกกัน และ vat_amount คิดจากบรรทัด standard เท่านั้น

4

ทดสอบส่วนลดท้ายบิลกับ VAT — ใส่ส่วนลด header บนใบที่มีทั้ง standard และ exempt → ส่วนลดต้องถูกปันลงทั้งสองบรรทัดตามสัดส่วน และฐาน VAT ต้องลดตามด้วย (ถ้าไม่ปัน ฐานภาษีจะเกินไปเท่าจำนวนส่วนลด) · ผลรวม header_discount_amount ทุกบรรทัดต้องเท่ากับ total_discount เป๊ะ

5
