คู่มือตั้งค่าเครือข่ายหลังติดตั้ง ERP แล้ว ฝั่ง Server (เครื่องที่รัน ERP) ต้องเปิด firewall และให้ Caddy ตอบชื่อ domain ฝั่ง Client (ทุกเครื่องที่เปิดเว็บ) ต้องรู้ว่าชื่อนั้นอยู่ที่ IP ไหน และต้องเชื่อ certificate ของ Caddy ทั้งสองฝั่งมีทางลัดเป็นคำสั่งเดียว และมีขั้นตอนทำเองไว้ใช้ตอนทางลัดไม่ผ่าน

Server: erp finish Client: erp-client-setup.ps1 ยังไม่ทดสอบบนเครื่องจริง: erp finish แบบไม่ dry-run · สคริปต์ client
สรุปใน 30 วินาที

Server: PowerShell แบบ Run as Administrator → C:\erp\erp.cmd finish (เปิด firewall 80 / 443 / 9443 และสร้าง C:\erp\erp-client-setup.ps1) · Client: copy erp-client-setup.ps1 ไปเครื่อง client แล้วคลิกขวา → Run with PowerShell → ปิดแล้วเปิด Chrome / Edge ใหม่ → เปิด https://erp.internal · ตั้ง IP ของ server ให้คงที่ก่อนเริ่ม ไม่อย่างนั้น hosts ของทุกเครื่องจะชี้ผิดเมื่อ IP เปลี่ยน

01 — ภาพรวม

เครื่องในออฟฟิศเข้า ERP อย่างไร

ทุก request จาก browser เข้าทาง Caddy บนเครื่อง server ที่เดียว Caddy แยกตามชื่อและพอร์ต แล้วส่งต่อไปที่ process ของ ERP ซึ่งฟังแค่ 127.0.0.1 ส่วน Redis / RabbitMQ / RustFS / Gotenberg ก็ฟังแค่ 127.0.0.1 ดังนั้นพอร์ตที่ต้องเปิดให้ LAN มีแค่พอร์ตของ Caddy

ชื่อ — erp.internal ไม่ใช่ชื่อบนอินเทอร์เน็ต ไม่มี DNS สาธารณะตอบให้ client ต้องรู้จากไฟล์ hosts หรือ DNS ของออฟฟิศ · certificate — ไม่มี public CA ไหนออก certificate ให้ชื่อ .internal ได้ Caddy จึงเป็น CA ของตัวเอง (tls internal) เครื่องที่ไม่เชื่อ CA นี้จะเห็นคำเตือน และ login ไม่ติด เพราะ cookie ของ login ตั้ง COOKIE_SECURE=true · เข้าด้วย IP ตรงๆ (https://192.168.1.10) ไม่ได้ เพราะ Caddy ตอบตามชื่อ และ certificate ออกให้ชื่อ ไม่ได้ออกให้ IP

02 — ก่อนเริ่ม

จด IP · ชื่อ · พอร์ต ให้เรียบร้อย

1

IP ของเครื่อง server ต้องคงที่

ดู IP ปัจจุบัน แล้วจองไว้ที่ router (DHCP reservation ผูกกับ MAC address) — วิธีนี้ดีกว่าตั้ง static IP ในเครื่อง เพราะ router จะไม่แจก IP นี้ให้เครื่องอื่น 

# บนเครื่อง server
Get-NetIPConfiguration | Where-Object IPv4DefaultGateway | Select-Object InterfaceAlias, IPv4Address
Get-NetAdapter | Where-Object Status -eq 'Up' | Select-Object Name, MacAddress   # MAC สำหรับจองที่ router

เครื่องที่มีหลาย IP (Wi-Fi + LAN, VPN, WSL / Hyper-V) — ใช้ IP ของการ์ดที่อยู่วงเดียวกับ client และควรต่อสาย LAN ไม่ใช่ Wi-Fi

2

ตั้งชื่อใน C:\erp\config\erp.env และ api.env

# erp.env
ERP_DOMAIN=erp.internal            # หน้าเว็บที่ผู้ใช้เปิด
ERP_API_DOMAIN=erp-api.internal    # backend สำหรับ Swagger / ระบบอื่น / support (เว้นว่าง = ไม่เปิด)
ERP_HTTP_PORT=80
ERP_HTTPS_PORT=443
FILES_PUBLIC_PORT=9443

# api.env — ต้องตรงตัวอักษรกับที่ browser เรียก (ชื่อ + พอร์ต)
STORAGE_S3_PUBLIC_ENDPOINT=https://erp.internal:9443
COOKIE_SECURE=true

แนะนำ suffix .internal (สงวนไว้ใช้ในเครือข่ายภายใน ไม่ชนกับชื่อจริงบนอินเทอร์เน็ต) · หลีกเลี่ยง .local — Windows / macOS ส่งชื่อ .local ไปถาม mDNS ก่อน ทำให้ช้าหรือหาไม่เจอ · แก้ชื่อแล้วสั่ง C:\erp\erp.cmd caddy เพื่อสร้าง Caddyfile ใหม่ และต้องสร้างสคริปต์ client ใหม่ (§10)

3

พอร์ต 80 / 443 / 9443 บน server ต้องว่าง

netstat -ano | findstr ":80 :443 :9443"
# ถ้าเป็น IIS (System / PID 4 บนพอร์ต 80):
net stop w3svc
Set-Service w3svc -StartupType Disabled

ถ้าปิดโปรแกรมที่ใช้พอร์ตไม่ได้ ให้เปลี่ยน ERP_HTTPS_PORT (เช่น 8443) — แต่ผู้ใช้ต้องพิมพ์พอร์ตใน URL ทุกครั้ง (https://erp.internal:8443)

03 — เครื่อง Server

ทางลัด: erp finish

ทำหลัง erp install ขึ้น ERP <version> is running แล้ว (ขั้นติดตั้งดูใน ERP Installer Guide §05) · เปิด PowerShell แบบ Run as Administrator — ไม่ใช่ Git Bash และไม่ใช่ PowerShell ธรรมดา (ถ้าไม่ใช่ Administrator ขั้น firewall / hosts / autostart จะถูกข้าม) 

C:\erp\erp.cmd finish --dry-run      # ดูก่อนว่าจะทำอะไร ไม่เปลี่ยนอะไร
C:\erp\erp.cmd finish                # ทำจริง — รันซ้ำได้ ข้อที่ผ่านแล้วจะข้าม

# ตัวเลือกที่เกี่ยวกับ LAN
C:\erp\erp.cmd finish --ip 192.168.1.10   # server มีหลาย IP — ระบุ IP ที่ client ใช้ (ฝังลงสคริปต์ client)
C:\erp\erp.cmd finish --no-hosts          # ออฟฟิศมี DNS ที่รู้จักชื่อแล้ว — สคริปต์ client ไม่แตะ hosts
ขั้นใน finishผลลัพธ์
superadmin password · ปิด staffถามรหัสใหม่ครั้งเดียว · ปิดบัญชี mock ถ้ายังใช้รหัส mock
autostartScheduled Task ERP (PM2 resurrect) — ถามรหัส Windows ของ user นี้ (--system = รันเป็น SYSTEM)
firewallลบแล้วสร้าง rule ERP (Caddy) ใหม่ — Inbound TCP ERP_HTTP_PORT, ERP_HTTPS_PORT, FILES_PUBLIC_PORT (ค่าเริ่มต้น 80, 443, 9443)
HTTPS บนเครื่องนี้= erp caddy-run --hosts: start Caddy, ให้ Windows เชื่อ CA, ใส่ 127.0.0.1 erp.internal erp-api.internal ลง hosts ของ server
client setup scriptเขียน C:\erp\erp-client-setup.ps1 ฝัง IP ของ server (IP LAN ตัวแรก หรือ --ip), ชื่อ domain, พอร์ต HTTPS และ CA — ถ้า server มีหลาย IP จะบอก IP อื่นไว้ในบรรทัดสรุป
statusจบด้วยตารางสรุป ✓ / ⚠ / ✗ — มี ✗ ให้แก้แล้วรัน finish ซ้ำ
ตรวจว่า IP ในสคริปต์ client ถูก

ดูบรรทัด client setup script ในตารางสรุป — ต้องเป็น hosts → <IP ที่จองไว้ใน §02> ถ้าได้ IP ของ WSL / VPN / Wi-Fi มาแทน ให้รันใหม่ด้วย erp client-setup --ip <IP ที่ถูก> (สร้างแค่สคริปต์ ไม่ทำขั้นอื่นซ้ำ)

04 — เครื่อง Server (ทำเอง)

ทีละขั้น เมื่อ finish ไม่ผ่าน

ทุกคำสั่งใน PowerShell แบบ Run as Administrator บนเครื่อง server

1

สร้าง Caddyfile และ start Caddy

C:\erp\erp.cmd caddy          # เขียน C:\erp\Caddyfile ใหม่จาก erp.env
C:\erp\erp.cmd caddy-run      # start Caddy ถ้ายังไม่รัน + ให้เครื่องนี้เชื่อ CA
C:\erp\erp.cmd status
2

เปิด Windows Firewall — 80, 443, 9443

Get-NetFirewallRule -DisplayName 'ERP (Caddy)' -ErrorAction SilentlyContinue | Remove-NetFirewallRule
New-NetFirewallRule -DisplayName 'ERP (Caddy)' -Direction Inbound -Protocol TCP -LocalPort 80,443,9443 -Action Allow

# ตรวจ
Get-NetFirewallRule -DisplayName 'ERP (Caddy)' | Get-NetFirewallPortFilter | Select-Object Protocol, LocalPort

rule นี้ใช้ได้ทุก profile (Domain / Private / Public) · ถ้าต้องการจำกัดให้แค่วง LAN ของออฟฟิศ เพิ่ม -RemoteAddress LocalSubnet · ถ้าเครื่องมี antivirus / firewall ของค่ายอื่น (ESET, Kaspersky ฯลฯ) ต้องเปิดพอร์ตในโปรแกรมนั้นด้วย เพราะ Windows Firewall rule ไม่มีผลกับมัน · เปลี่ยนพอร์ตใน erp.env เมื่อไหร่ ต้องแก้ rule ตาม

3

ตั้ง network profile เป็น Private

Get-NetConnectionProfile
Set-NetConnectionProfile -InterfaceAlias 'Ethernet' -NetworkCategory Private

ไม่บังคับสำหรับ rule ข้างบน แต่ Public profile ปิด ping และ network discovery ทำให้ทดสอบจาก client ยากขึ้น

4

hosts ของเครื่อง server เอง (ถ้าเปิดเว็บบนเครื่องนี้ด้วย)

C:\erp\erp.cmd caddy-run --hosts   # ใส่ 127.0.0.1 erp.internal erp-api.internal ให้
5

ส่งออก CA + สร้างสคริปต์ client

C:\erp\erp.cmd ca                              # C:\erp\erp-local-ca.crt + วิธีติดตั้งของแต่ละ OS
C:\erp\erp.cmd client-setup --ip 192.168.1.10   # C:\erp\erp-client-setup.ps1
C:\erp\erp.cmd client-setup --no-hosts          # เมื่อใช้ DNS ของออฟฟิศ (§07)

ไฟล์ .crt เป็น certificate สาธารณะ แจกได้ — แต่ห้ามแจกโฟลเดอร์ C:\erp\caddy-data ซึ่งมี private key ของ CA (§11)

6

ทดสอบจากตัว server

curl.exe -sS -o NUL -w "%{http_code}`n" --ssl-no-revoke https://erp.internal/.erp-probe        # 200
curl.exe -sS -o NUL -w "%{http_code}`n" --ssl-no-revoke https://erp.internal:9443/.erp-probe   # 200 = Caddy ฟังพอร์ตไฟล์แนบ
Test-NetConnection 192.168.1.10 -Port 443                                                     # TcpTestSucceeded : True
05 — เครื่อง Client

ทางลัด: erp-client-setup.ps1

ทำทุกเครื่องที่จะเปิด ERP ใน browser · ไฟล์เดียว ไม่ต้องติดตั้งอะไรเพิ่ม · ใช้ได้กับ Windows 10 / 11

1

เอาไฟล์มาที่เครื่อง client

ทางใดทางหนึ่ง: copy C:\erp\erp-client-setup.ps1 จาก server ด้วย USB / shared folder · หรือเปิด ERP Console (http://127.0.0.1:3399 บน server) → Overview → การ์ด Web access → Download erp-client-setup.ps1 แล้วส่งต่อให้เครื่อง client

2

คลิกขวา → Run with PowerShell

สคริปต์ขอสิทธิ์ Administrator เอง (กด Yes ที่ UAC) แล้วทำ 3 อย่าง:

ขั้นทำอะไร
certificateเขียน CA ลง C:\ProgramData\erp\erp-local-ca.crt แล้ว certutil -addstore Root — เชื่อทั้งเครื่อง (ทุก user) · มีแล้วข้าม
hostsเพิ่ม 192.168.1.10 erp.internal erp-api.internal # erp-installer · บรรทัดเดิมของสคริปต์ถูกแทนที่ · บรรทัดอื่นที่ map ชื่อเดียวกันถูก comment ทิ้ง (กันมีสองคำตอบ) · ipconfig /flushdns
ทดสอบcurl.exe ไปที่ https://erp.internal/.erp-probe แบบเดียวกับ Chrome / Edge (Schannel) — บอกแยกว่า “ต่อไม่ได้” หรือ “ต่อได้แต่ยังไม่เชื่อ certificate”
 
# ผลที่ถูกต้อง
  OK    certificate: added to Trusted Root (all users of this PC)
  OK    hosts: 192.168.1.10 erp.internal erp-api.internal
  OK    https://erp.internal/ answers and the certificate is trusted
Done. Close and reopen Chrome / Edge, then open https://erp.internal/

ถ้าคลิกขวาไม่มี “Run with PowerShell” หรือหน้าต่างปิดทันที ให้เปิด PowerShell แบบ Administrator แล้วสั่ง powershell -ExecutionPolicy Bypass -File C:\Users\<user>\Downloads\erp-client-setup.ps1

3

ปิด browser ให้หมดแล้วเปิดใหม่

Chrome / Edge อ่าน Trusted Root ตอนเปิดเท่านั้น — ต้องปิดทุกหน้าต่าง (รวมที่ค้างใน system tray) · Firefox ใช้ที่เก็บ certificate ของตัวเอง: Settings → Privacy & Security → Certificates → View Certificates → Authorities → Import C:\ProgramData\erp\erp-local-ca.crt → ติ๊ก “Trust this CA to identify websites”

รันซ้ำได้เสมอ

สคริปต์ idempotent — server เปลี่ยน IP, เปลี่ยนชื่อ domain หรือ CA เปลี่ยน ให้สร้างสคริปต์ใหม่บน server แล้วรันซ้ำบน client ได้เลย · ถอนออก: powershell -ExecutionPolicy Bypass -File erp-client-setup.ps1 -Remove (ลบบรรทัด hosts ของตัวเอง + ลบ CA)

06 — เครื่อง Client (ทำเอง)

เมื่อรันสคริปต์ไม่ได้

เช่น Group Policy บังคับ AllSigned, antivirus บล็อก .ps1 หรือ IT ของลูกค้าต้องการทำเอง · ใช้ PowerShell แบบ Run as Administrator บนเครื่อง client

1

ชื่อ → IP ของ server (hosts)

Add-Content -Path C:\Windows\System32\drivers\etc\hosts -Value "192.168.1.10  erp.internal erp-api.internal"
ipconfig /flushdns
Resolve-DnsName erp.internal      # ต้องได้ 192.168.1.10

หรือเปิด Notepad แบบ Run as administrator → File → Open → C:\Windows\System32\drivers\etc\hosts (เลือก All Files) → เพิ่มบรรทัดท้ายไฟล์ · ตรวจว่าไม่มีบรรทัดอื่นที่ map erp.internal ไป IP เก่า · บาง antivirus ล็อกไฟล์ hosts — ต้องปิด protection ชั่วคราว

2

เชื่อ CA ของ Caddy

# copy C:\erp\erp-local-ca.crt จาก server มาก่อน (หรือดาวน์โหลดจากการ์ด Web access)
certutil -addstore -f Root C:\Users\<user>\Downloads\erp-local-ca.crt
Get-ChildItem Cert:\LocalMachine\Root | Where-Object Subject -like '*Caddy*'   # ต้องเห็น Caddy Local Authority

ทางคลิก: ดับเบิลคลิกไฟล์ .crt → Install Certificate → Local Machine → Place all certificates in the following store → Trusted Root Certification Authorities → Finish · ต้องเป็น Trusted Root ไม่ใช่ Personal หรือ Intermediate

3

ทดสอบ

Test-NetConnection erp.internal -Port 443        # TcpTestSucceeded : True → ชื่อ + firewall ผ่าน
Test-NetConnection erp.internal -Port 9443       # ไฟล์แนบ / รูป
curl.exe -sS -o NUL -w "%{http_code}`n" --ssl-no-revoke https://erp.internal/.erp-probe   # 200 = certificate ผ่านด้วย

ผ่านแล้วปิด / เปิด Chrome / Edge ใหม่ (§05 ขั้น 3)

OS ของ clienthostsเชื่อ CA
macOSsudo sh -c 'echo "192.168.1.10 erp.internal erp-api.internal" >> /etc/hosts'sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain erp-local-ca.crt
Ubuntusudo sh -c 'echo "192.168.1.10 erp.internal erp-api.internal" >> /etc/hosts'sudo cp erp-local-ca.crt /usr/local/share/ca-certificates/ && sudo update-ca-certificates
Android / iOSแก้ hosts ไม่ได้ — ต้องใช้ DNS ของ router (§07)ติดตั้ง .crt เป็น CA (Android: Settings → Security → Install certificate · iOS: ติดตั้ง profile แล้วเปิด Full Trust ใน About → Certificate Trust Settings)
07 — ทางเลือก

ใช้ DNS ของ router / ออฟฟิศแทน hosts

เหมาะเมื่อมีเครื่อง client เยอะ มีมือถือ / tablet หรือ IP ของ server อาจเปลี่ยน — แก้ที่เดียวทุกเครื่องได้ผล · แต่ทุกเครื่องยังต้องเชื่อ CA (DNS แก้แค่เรื่องชื่อ)

ที่ตั้ง DNSวิธี
router ทั่วไปหน้า admin ของ router → LAN / DHCP → Static DNS / Local DNS / DNS host mapping → เพิ่ม erp.internal และ erp-api.internal → 192.168.1.10 (ชื่อเมนูต่างกันแต่ละยี่ห้อ — router บ้านหลายรุ่นไม่มีเมนูนี้)
